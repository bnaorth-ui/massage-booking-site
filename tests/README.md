# เทสต์ของระบบจองนวด

เทสต์อัตโนมัติด้วย [Playwright](https://playwright.dev) ครอบคลุมเว็บ 4 หน้า (ผู้ใช้ ร้านนวด พนักงาน แอดมิน)
เทสต์ทุกไฟล์ใช้ **ข้อมูลจำลอง** (ดักคำขอไป Supabase และบริการภายนอก) จึงไม่แตะฐานข้อมูลจริงและไม่ต้องมีรหัสลับใด ๆ

## วิธีรัน

```bash
cd tests
npm install                      # ติดตั้ง Playwright
npx playwright install chromium  # ติดตั้งเบราว์เซอร์ (ครั้งแรก)
npm test                         # รันทุกไฟล์ แล้วสรุปผล
node run-all.js . ins            # รันเฉพาะไฟล์ที่ชื่อมีคำว่า ins
node t_ins_cust.js               # รันไฟล์เดียว ดูรายข้อ PASS/FAIL
```

ตัวแปรที่ปรับได้:

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `PAGES_DIR` | โฟลเดอร์ที่มี `customer-booking.html` ฯลฯ | ใช้ `customer/index.html`, `shop/index.html`, `staff/index.html`, `admin/index.html` ใน repository |
| `CHROMIUM_PATH` | ตำแหน่งเบราว์เซอร์ | ใช้ตัวที่ Playwright ติดตั้งให้ |
| `JOBS` | จำนวนไฟล์ที่รันพร้อมกัน | 4 |
| `TIMEOUT_MS` | เวลาสูงสุดต่อไฟล์ | 300000 |

ผลลัพธ์: ไฟล์ที่ `ok` คือทุกข้อผ่าน ไฟล์ที่ขึ้น `BAD` มีข้อไม่ผ่าน (`FAIL`) ค้างเกินเวลา (`TIMEOUT`) หรือโปรแกรมหยุดกลางทาง (`CRASH`)
คำสั่งจบด้วยรหัส 1 เมื่อมีไฟล์ผิดปกติ

## ข้อควรรู้

- เทสต์บางไฟล์เป็น "ชุดตัวแปรปรับพฤติกรรม" ระบุไว้ในบรรทัดแรกของไฟล์ เช่น `// RUN-ENV: NOFAV=1` ตัวรัน `run-all.js` จะอ่านและตั้งตัวแปรให้เอง ถ้ารันไฟล์เดี่ยวด้วยมือต้องตั้งเอง

- ชื่อไฟล์ขึ้นต้นด้วย `t_` และตั้งตามเรื่องที่ทดสอบ เช่น `t_ins_*` หน้าติดตั้งแอป `t_map_*` ตัวเลือกแผนที่ `t_stshare_*` ลิงก์แชร์พนักงาน
- เทสต์ที่เกี่ยวกับแผนที่ใช้ `window.L` จำลอง เพราะไม่โหลด Leaflet จริง ต้องลองแผนที่จริงบนมือถือเองอีกครั้ง
- เทสต์ไม่ได้ตรวจ SQL หรือนโยบาย RLS บนฐานข้อมูลจริง ต้องตรวจใน Supabase แยกต่างหาก
- เทสต์ `t_pushui.js` และ `t_watchui.js` เปิดเว็บเซิร์ฟเวอร์ชั่วคราวที่พอร์ต 8099 อย่ารันสองไฟล์นี้พร้อมกัน (ใช้ `JOBS=1` หรือรันแยก)
- เทสต์ 6 ไฟล์ที่ล้าสมัย (ถูกแทนที่แล้ว รอตัดสินใจลบ) แยกไว้ใน `_needs-review/` (ไม่ถูกรันอัตโนมัติ) ดูเหตุผลในไฟล์ README ในโฟลเดอร์นั้น
